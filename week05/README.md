# Project 5 — Linear Regression from Scratch

A NumPy implementation of **ordinary least squares, Ridge and Lasso**, tested against scikit-learn, followed by an assumption audit on the **NYC Airbnb 2019** listings data.

## What this project demonstrates

- **OLS** via `numpy.linalg.lstsq` (works with singular and wide matrices).
- **Ridge** via `numpy.linalg.solve` (no explicit matrix inversion).
- **Lasso** via cyclic coordinate descent with soft thresholding.
- Intercept fitting by centering; **the intercept is not penalized**.
- Comparison tests with measured maximum coefficient, intercept, prediction and R² differences; input-validation and edge-case checks.
- A real-data pipeline using Week 04 leakage-safe preprocessing, training-only cross-validation, residual diagnostics, a log-target intervention and a smearing correction.
- Coefficient interpretation, seven-numeric-feature VIF investigation and an exploratory Ridge-versus-Lasso sparsity comparison.

## Run the tests

From the `week05` folder:

```bash
python3 test_linreg.py
```

The current script contains **32 written `assert` statements** (some executed repeatedly for multiple alpha values and data shapes). It prints PASS messages as groups complete and stops on any uncaught failure. It does not yet report a formal aggregate PASS/FAIL counter. Exact floating-point differences can vary by operating system, installed library versions and linear algebra backend.

The custom estimator supports:

```python
from linreg import MyLinearRegression

model = MyLinearRegression(alpha=1.0, penalty="l2", fit_intercept=True)
model.fit(X_train, y_train)
predictions = model.predict(X_new)
r2 = model.score(X_new, y_new)
diagnostics = model.residual_report(X_new, y_new)
```

`X_train`, `y_train` and `X_new` are placeholders representing user-provided arrays. When predicting **one observation with multiple features**, pass a two-dimensional row (such as `[[1, 2, 3]]`).

`penalty="l2"` with positive alpha is Ridge, `penalty="l1"` with positive alpha is Lasso, and `alpha=0` routes to OLS. Lasso iteration count is available as `n_iter_` following an L1 fit.

## Real-data setup and evaluation

- Original dataset: **48,895 rows × 16 columns**. Excluded 11 listings with nonpositive `price`.
- Modeling rows: **48,884**; training **39,107**; test **9,777**, using one 80/20 split with `random_state=42`.
- Baseline: predict the training mean price (`DummyRegressor`).
- Preprocessing lives **inside** the modeling pipeline: imputing missing values, scaling/log transforms and categorical encoding are fit on each training fold.
- Initial dollar-scale Ridge alpha selected through 5-fold CV: **10**.
- Investigated `log1p(price)` plus inverse `expm1` and a training-only **Duan smearing factor** to improve dollar-scale calibration.
- Final smearing-corrected log-price Ridge alpha selected through training-only CV: **0.1**; factor fitted on full training data: **1.1694586946211147**.
- After selection, the held-out test set was evaluated once. **Do not retune based on these test results.**

| Model / evaluation | R² | MAE (USD) |
|---|---:|---:|
| Mean baseline — train | 0.0000 | 92.9508 |
| Mean baseline — test | −0.0001 | 91.2818 |
| Final Ridge + smearing — train | 0.1206 | 66.2438 |
| Final Ridge + smearing — training CV (pooled OOF) | 0.1185 | 66.4963 |
| **Final Ridge + smearing — held-out test** | **0.1524** | **65.4988** |

The test MAE improves approximately **28.2%** over the mean baseline, but test R² remains modest. Strong skewness, extreme listings, heteroscedasticity and geographic structure limit the reliability of a simple linear pricing model. See `report.md` for the full assumption-by-assumption interpretation.

## Correctness and interpretation highlights

- OLS coefficient difference on reference synthetic data: **`4.440892098500626e-16`**; Ridge alpha values 0.1, 1, 10 and 100 matched within `1e-10`; Lasso alpha values 0.001, 0.01 and 0.1 within `1e-4`.
- Training-only numeric-feature VIF range: **1.0097–1.5115** for seven median-imputed raw features; this does *not* describe the full one-hot-encoded design matrix.
- Lasso at exploratory alpha 0.01 retained **9 of 105** transformed features; this is selection under that penalty, not proof the omitted features lack meaning.
- Ridge room-type coefficients imply approximately **107.38% higher predicted `(price + 1)`** for an otherwise similar Entire home/apartment listing than a Private room listing; this is an *association*, not a causal estimate.
- Normality and constant-error-variance assumptions were **not fully restored** by the log-target transformation.

## Important methodological distinction

**`linreg.py` is the from-scratch implementation under test.** The large-scale real-data experiments in `analysis.ipynb` use **scikit-learn Ridge and Lasso** with the Week 04 preprocessor because of estimator integration and computational practicality. The report does not present these as fits from the custom class.

## Known limits

- `residual_report()` offers exploratory diagnostics; Durbin–Watson on arbitrary cross-sectional row order cannot establish independence.
- The custom Lasso loop lacks an explicit warning when reaching the hard maximum iteration count.
- All-category one-hot columns can introduce exact dependencies; standalone category coefficients are not causal or unambiguous category premiums.
- A single global smearing factor may be inadequate under conditional heteroscedasticity.
- Reproducing the notebook requires Week 04 files; running only the standalone tests does not.
